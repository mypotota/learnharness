## Context

LearnHarness 的 Android 移植采用"内嵌桌面服务端"路线:APK 里打包 Termux Node 24 + 桌面 Next.js standalone 服务,启动时在 127.0.0.1:41100 起服务,WebView 直接加载它。P0(真机验证)/P1(payload 产出脚本 `mobile/scripts/prepare-mobile-runtime.mjs`)已完成;本轮完成 **P2**(WebView 加载 loopback 服务端的完整闭环)和 **P3**(`run_demo` 渲染服务:隐藏 WebView 暴露 `POST /render`,由 `LH_RENDER_SERVICE_URL` 选择,替代桌面 puppeteer/Chrome 路径)。用户已拍板:abi 只保留 arm64-v8a。

`renderSvg`/PDF 渲染无需 P3 处理:它们走 resvg / pdfjs+@napi-rs/canvas,prepare 脚本已换入 android-arm64 原生包,只有 `runDemo` 需要浏览器。

## A. P2:Android 闭环

### 1. `mobile/android/app/build.gradle`
- 删除 `ndkVersion`、`abiFilters "x86_64"`(保留 arm64-v8a)、`externalNativeBuild` 两处块(defaultConfig 内 cmake + 顶层)。
- sourceSets:`assets.srcDirs += ["$buildDir/generated/lh-assets"]`、`jniLibs.srcDirs += ["$buildDir/generated/lh-jniLibs"]`(替换现有 node-assets 行)。
- 删除 `syncNodeRuntime`/`syncCorePlugins`/`syncCommunityPlugins` 三个任务及其 dependsOn;新增 `prepareMobileRuntime` Exec 任务:`workingDir` = mobile/,命令 `node scripts/prepare-mobile-runtime.mjs`,`preBuild.dependsOn` 它;配 inputs/outputs(`.next/standalone`、脚本、`.cache/runtime` → 两个产物)让无变化时跳过。
- 新增 `packaging { jniLibs { useLegacyPackaging = true } }`(AGP 8.7 下 `android:extractNativeLibs="true"` 的等价形式;node 必须落到只读的 `nativeLibraryDir` 才能被 exec,API 29+)。

### 2. `mobile/android/app/src/main/AndroidManifest.xml`
- 增加 `<uses-permission android:name="android.permission.RECORD_AUDIO"/>`、`CAMERA`(getUserMedia 用;运行时权限提示留待 P4)。

### 3. 新建 `ServerRuntime.java`(替代被删除的 NodeRuntime)
- `start(context, onReady, onFailure)`:后台线程执行——
  - ZIP 解压:APK `lastUpdateTime` 变化时把 `assets/lh-server.zip`(`java.util.zip`)解到 `filesDir/lh-server`,写 stamp 标记;
  - 启动:`ProcessBuilder(nativeLibraryDir/liblh-node.so, server.js)`,`directory(filesDir/lh-server)`,env:`NODE_ENV=production`、`PORT=41100`、`HOSTNAME=127.0.0.1`、`LH_DATA_DIR=filesDir/data`、`LH_AUTH_FILE=filesDir/auth.json`、`LD_LIBRARY_PATH=filesDir/lh-server/runtime/lib`、`LH_RENDER_SERVICE_URL=http://127.0.0.1:41101/render`、`NEXT_TELEMETRY_DISABLED=1`、`TMPDIR`/`HOME` 卫生变量;**不设** `LH_DESKTOP_SERVER`/`LH_DESKTOP_API_SECRET`(browser-only 模式,见 `src/server/desktop-access.ts`);
  - 日志:stdout/stderr 重定向追加到 `filesDir/logs/server.log`;
  - 就绪探测:轮询 `Socket(127.0.0.1,41100)`;进程退出则重启(有界,如 5 次),耗尽后回调 onFailure,由 overlay 显示错误。

### 4. `MainActivity.java` 重写
- 移除 `NodeRuntime.start`;保留 LocalProxy/SecureStore 插件注册;`setTheme(R.style.AppTheme.NoActionBar)`;启动 ServerRuntime + RenderService。
- 启动画面:`addContentView` 全屏 splash 覆盖层;就绪回调(UI 线程)→ 移除 overlay → `bridge.getWebView().loadUrl("http://127.0.0.1:41100/")`;失败回调 → overlay 上显示错误文案。
- 返回手势:`canGoBack() ? goBack() : finish()`;API 33+ 走 `OnBackInvokedDispatcher`,低版本走 `onBackPressed`。

### 5. Capacitor 配置
- `mobile/capacitor.config.ts`:`server.url = "http://127.0.0.1:41100/"`,`server.allowNavigation = ["127.0.0.1","localhost"]`;实现时跑 `npx cap sync android` 再生成 android assets 下被 gitignore 的 `capacitor.config.json`(本地生效,不入库)。

### 6. 删除
- `NodeRuntime.java`、`src/main/cpp/`(CMakeLists.txt、node-starter.cpp、node_include/)。

## B. P3:渲染服务

### 7. 新建 `RenderService.java`
- loopback HTTP 服务:绑定 `127.0.0.1:41101`,Java 线程 accept 循环,手写最小 HTTP 解析(Content-Length 读体、`Connection: close` 响应;org.json 解析;单任务串行)。
- 隐藏渲染 WebView:1×1px 挂在 activity decor 上(可见,保证 rAF 有帧);JS 开启、`setAllowFileAccess(false)`、**不** addJavascriptInterface;`loadDataWithBaseURL(null, html, ...)` 得 opaque origin(对齐桌面 about:blank 隔离语义)。
- DemoRunResult 采集:console 错误 = `WebChromeClient.onConsoleMessage`(type error);page 错误 = 注入采集 shim(`window.onerror` + `unhandledrejection` 收集进数组),插在 `<head>` 后(无 head 则 doctype 后);failed requests = `WebViewClient.onReceivedError`;probe = settle 后 `evaluateJavascript`,异常计入 pageErrors(`probe failed: …`);任务间 `loadUrl("about:blank")` 退役文档。
- 响应:成功返回 DemoRunResult JSON;服务忙/异常返回 `{error}`。

### 8. `src/agent/subagents/headless.ts`(服务端)
- 新增 `renderServiceUrl()`:`LH_RENDER_SERVICE_URL` 每次调用时读取(测试友好)。
- 设置时:`realHeadless.runDemo` 改走远程(`fetch` POST `{html, settleMs, probe}`,`AbortSignal.timeout` ~90s;非 200 / `{error}` / 超时 → throw,对齐 run_demo 工具的 "HEADLESS ERROR" 路径;返回体校验并规整为 `DemoRunResult`);`available()` true、`unavailableReason()` null。未设置时桌面 helper/Chrome 路径**一行不动**。

### 9. 测试 + 文档
- 新增 `tests/headless-remote-render.test.ts`(node:test + 本地 http fixture):env 未设时走桌面逻辑不发网络;设置后请求体/响应映射/错误映射。
- 更新 `docs/mobile-android-port.md`:Status 表、剩余工作清单、固定端口 41100/41101 约定、`LH_RENDER_SERVICE_URL` 说明;`docs/development.md` env 表加 `LH_RENDER_SERVICE_URL` 行(标注 mobile-only)。
